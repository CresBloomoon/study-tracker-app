# ADR-005: マイグレーション運用（Postgres）

## ステータス
Accepted

## 文脈
- StudyLogは一次データであり、消失や破壊的変更は許容できない
- DBスキーマ変更は履歴として残り、再現可能である必要がある
- 変更前DBを読める互換性、または明示的な移行手順を必ず用意する

## 決定
- DBスキーマ変更は **必ずマイグレーション** として管理する
- Prisma Migrate を採用する
- 本番適用は `prisma migrate deploy` を用いる
- `prisma db push` は原則禁止（緊急時でも使わない）

## 変更の方針（破壊的変更を避ける手順）
- 破壊的変更（カラム削除、型変更、NOT NULL化など）は一発で行わない
- 原則として次の順で段階移行する：
  1) 追加（nullableで追加）
  2) backfill（データ移行SQL）
  3) 並行稼働（旧/新どちらでも読める）
  4) 切替
  5) 削除（十分な期間後）

## 影響
- 変更の手間は増えるが、データ破壊リスクが激減する
- スキーマ変更のレビュー・ロールバックが可能になる
