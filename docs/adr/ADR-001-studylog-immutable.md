# ADR-001: StudyLogは編集・削除不可（追加のみ台帳）とする

## Status
Accepted

## Date
2026-01-06

## Context
CPA-Dashboard-Core v1 の最上位原則（憲法第1条）は「学習データ（一次データ）は絶対に消えない」である。

学習記録（StudyLog）は週次報告・日次集計の基礎となる一次データであり、ここが変動すると集計の意味が崩れる。
また、既存 CPA-Dashboard は変更の経緯が追えずブラックボックス化しているため、v1では仕様と責務を極力単純に保ちたい。

学習時間はユーザの自己管理指標であり、記録を容易に改変できる設計は「都合の良い修正」や「事故による破壊」を招きやすい。
一方で、誤記録（科目の選択ミスや誤った停止操作）も現実的に起こり得る。

## Decision
v1において StudyLog は以下の通り扱う。

- StudyLog は **作成のみ（追加のみ）** とする
- **編集・削除・無効化** は提供しない
- 日付の手動指定も提供しない（JSTの当日へ自動紐づけ）
- 集計は StudyLog から派生生成する（一次データの意味を固定する）

誤記録が発生した場合は、v1ではシステム側で救済（修正・無効化）を提供せず、運用上の注意に委ねる。

## Consequences
### Positive
- 一次データが不変となり、集計（DailySummary/週次表示）の意味が安定する
- 実装が単純になり、責務の混線とブラックボックス再生産を防げる
- データ保護の観点で「削除事故」「編集事故」を根本的に回避できる
- 将来、監査可能性（変更履歴を追える）を求める場合にも拡張方針を取りやすい
  - 修正が必要なら「修正」ではなく「追加（訂正ログ）」として設計できる

### Negative / Trade-offs
- 誤記録が集計に反映され続ける（数字が汚れる）
- ユーザが「昨日分に付け替える」等の柔軟な運用ができない
- UXとしては不便になる可能性がある

### Mitigations (v1 scope)
- 保存失敗により学習が無かったことになる事故を防ぐため、
  未保存の計測結果（TimerSession）を localStorage に保持し、再試行可能とする
- 将来、誤記救済が必須になった場合は、編集・削除ではなく
  「訂正レコードの追加」等、一次データ不変を維持する方式を検討する
