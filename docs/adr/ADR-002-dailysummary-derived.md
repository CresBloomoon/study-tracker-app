# ADR-002: DailySummaryはDBに保存せず派生データとして扱う

## Status
Accepted

## Date
2026-01-06

## Context
CPA-Dashboard-Core v1 では、学習記録（StudyLog）を一次データとし、
日次・週次の集計結果をユーザに提示することを目的としている。

既存 CPA-Dashboard では、集計結果や表示用データがどこまで一次データなのかが不明瞭となり、
仕様変更やバグ修正時に「どのデータが正なのか分からない」状態が発生していた。

また、本プロジェクトの最上位原則（憲法第1条）は
「学習データ（一次データ）は絶対に消えない」であり、
派生データの破損や不整合は、一次データの安全性より優先されるべきではない。

日次集計（DailySummary）は StudyLog から常に再計算可能であり、
v1のデータ量・性能要件において、事前保存を行う必然性は低い。

## Decision
v1において DailySummary は以下の方針で扱う。

- DailySummary は **StudyLog から生成される派生データ** とする
- DBに保存しない
- 表示要求時にオンデマンドで集計する
- 集計ロジックはアプリケーション層（UseCase）に置く

週次・月次の集計についても、DailySummary または StudyLog の再集計で対応する。

## Consequences
### Positive
- 一次データ（StudyLog）のみを真実の情報源（Single Source of Truth）として扱える
- 集計データ破損時も再計算により復旧可能
- DBスキーマが単純になり、マイグレーションリスクが低下する
- 将来、集計仕様が変わっても過去データの意味が変わらない

### Negative / Trade-offs
- 集計処理が毎回実行されるため、データ量増加時に性能劣化の可能性がある
- 集計ロジックが複雑化すると、UseCase層の責務が増える

### Mitigations (v1 scope)
- v1ではデータ量が限定的であるため、性能問題は考慮しない
- 性能要件が顕在化した場合は、
  - 日次集計テーブルの導入
  - キャッシュ層の追加
  を **新しいADRとして明示的に判断** した上で行う
- 集計テーブル導入時は、必ず既存DBを読めるマイグレーション手順を用意する
