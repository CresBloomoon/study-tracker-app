# ADR-014: Use PAUSED Instead of STOPPED for Resumable Timer State

## 背景（なぜ必要か）

タイマー機能において、現在の状態 `STOPPED` は以下の意味を担っている。

- 計測は停止している
- セッションは終了していない
- 再開（Resume）が可能
- Record 操作が可能

しかし `STOPPED` という名称は一般的に

- 完全停止
- 終了状態
- 再開不可

といった意味合いで解釈されやすく、  
**実際の挙動（＝一時停止）と乖離がある**。

この乖離は、将来の実装・設計・UI判断時に
「この STOPPED は一時停止なのか？終了なのか？」
という認知負荷と誤解を生む。

## 決定内容（何を決めたか）

- 再開可能な停止状態を表す名称として  
  **`STOPPED` ではなく `PAUSED` を採用する**
- 意味論として以下を明確に分離する

| 状態名 | 意味 |
|------|------|
| RUNNING | 計測中 |
| PAUSED | 一時停止中（再開可能・Record可能） |
| IDLE | セッションが存在しない概念状態 |

- `IDLE` は引き続き **DBには存在しない概念状態**とする

## 採用理由（なぜそうしたか）

- `PAUSED` は「一時停止・再開前提」という意味が一義的である
- UI・API・状態遷移図・ドキュメント間の意味統一が容易になる
- 将来、以下の状態を追加する余地を自然に残せる
  - FINISHED（完全終了）
  - CANCELED（破棄）
- 現段階では外部公開APIが存在せず、
  **破壊的変更のコストが最小**である

## 却下した代替案

### 代替案1：STOPPED のままコメントで意味を補足する
- コメントやドキュメント依存になり、コード単体で意味が伝わらない
- 状態名が誤解を誘発する点は解消されない

### 代替案2：STOPPED と PAUSED を両立させる
- 状態数が増え、UseCase・ガード条件が複雑化する
- 現時点では過剰設計

## 影響範囲

- Prisma enum（TimerState）
- Timer 関連 UseCase / Repository
- `/timer/current` レスポンス
- 状態遷移図（TIMER_STATE_MACHINE.mmd）
- UI 側の状態判定（将来実装）

※ DB構造自体の変更は enum 名称変更のみであり、
  **データ構造の破壊は伴わない**
