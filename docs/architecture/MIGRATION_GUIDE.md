# マイグレーション運用ガイド（v1）

## 目的
- DBスキーマ変更を安全に、再現可能に行う
- 変更前DBが読める互換性、または明示的移行手順を必ず提供する

## 原則（絶対）
- スキーマ変更は必ず migration としてコミットする
- `db push` は使わない
- StudyLog（一次データ）を破壊する変更は禁止

## 開発環境
- 変更作成：prisma migrate dev
- ローカル検証：prisma migrate dev
- 本番適用：prisma migrate deploy

## 破壊的変更の手順（例：カラム追加→必須化）
1. nullable でカラム追加
2. backfill SQL で埋める
3. アプリを新カラム参照に切り替える（旧カラムも読める状態を維持）
4. NOT NULL 制約を追加
5. 旧カラムを削除（後日）

## 変更前DBを読めるようにする方法
- 旧カラムを残して互換運用する
- 互換VIEWを用意する
- 明示的移行SQL（backfill）を同梱する
